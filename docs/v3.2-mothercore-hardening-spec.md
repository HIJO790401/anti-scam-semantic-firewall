# Anti-Scam Semantic Firewall
## v3.2 母核對齊硬化規格（Demo 到「難挑毛病」版本）

> 目標：把目前前置 Demo，升級成「可以被技術審查、風控審查、流程審查同時檢視」且不容易被抓漏洞的展示版本。

---

## 0. 先講結論：要加強到什麼程度才算「過關」？

若你的目標是「對上母核邏輯，外部很難挑毛病」，最少要達成三層過關：

1. **邏輯一致性過關（Core Alignment）**
   - 每個風險判定都能回溯到「母核規則編號 + 證據片段 + SCBKR 軸變化」。
2. **穩定性過關（Regression Stability）**
   - 固定測試集每次跑分不能漂移超過門檻。
3. **審查可驗證過關（Auditability）**
   - 任一輸出可被重播，且產出一致的判斷與理由。

---

## 1. 母核邏輯對齊框架（先定義，不先寫程式）

把母核拆成三層，避免「概念對齊、實作失焦」：

### A 層：不可變原則（Constitution Layer）
- 例如：
  - 不要求使用者直接信任訊息內連結。
  - 牽涉金流 + 急迫 + 非可信通道時，優先高風險。
  - 責任不可追溯時，風險不可關閉（NON-CLOSABLE）。

### B 層：推理規則（Inference Layer）
- 目前 SCBKR + pattern 屬於此層。
- 每條規則必須有：
  - `rule_id`
  - `trigger_condition`
  - `impact_on_axes`
  - `impact_on_risk`

### C 層：輸出治理（Decision Policy Layer）
- 例如：
  - `FATAL` 一律輸出「立即停止 + 官方管道複核」。
  - `SAFE` 不代表保證安全，只代表未命中高危語意。

## 2. Demo 升級「難挑毛病」的硬指標

> 沒有指標就無法證明你更強。

### 2.1 規則覆蓋率（Rule Coverage）
- 母核規則覆蓋率 ≥ **95%**（每條規則都要有至少一筆正例測資觸發）。
- 每條規則要有至少一筆反例，避免過度觸發。

### 2.2 回歸穩定性（Regression）
- 固定語料集（建議 200~500 筆）每次版本比對：
  - 風險等級變動率 ≤ **3%**（除非標記為策略調整版本）。
  - 非預期降級（FATAL→RISK/SAFE）數量必須為 **0**。

### 2.3 可解釋一致性（Explainability）
- 100% 案例能輸出：
  - 命中規則列表
  - SCBKR 五軸狀態
  - 人類可讀建議
- 禁止只輸出「分數」卻沒有可讀理由。

### 2.4 誤判控制（False Positive / False Negative）
- 高風險類別（金融釣魚、假投資、驗證碼騙取）漏判率需持續下降。
- 可先以階段目標設定：
  - 高風險漏判率 < **5%**
  - 一般通知誤判率 < **8%**

## 3. 你這版 Demo 的優勢（要保留）

1. **可解釋性高**：規則可讀、輸出可讀。
2. **本地執行隱私好**：不送出輸入文本。
3. **場景化能力好**：標準/專業/長輩模式 + 朗讀 + 匯出。

> 升級時請保留這三點，這是你的差異化護城河。

---

## 4. 目前最容易被挑毛病的點（優先修）

1. **規則字典仍偏靜態**：易被同義改寫/新話術繞過。
2. **缺少正式 benchmark 報告**：目前難以量化證明「比別人強」。
3. **缺少規則版本化與審計序號**：外部審查時不易追責與重播。
4. **i18n 尚未全頁覆蓋**：中英一致性還有落差。

## 7. Demo 驗收標準（對外可說服）

只要同時達成以下條件，你就可以很有底氣說「這不是玩具 Demo」：

1. 有固定 benchmark 且可重跑。  
2. 有規則版本與變更紀錄。  
3. 每個決策可回溯可解釋。  
4. 有長輩/一般/專業三情境完整流程示範。  
5. 關鍵高風險案例漏判率達到你設定門檻。
