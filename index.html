ROLE INTEGRITY ｜ Ex(y)=π 治理層
Model Role = Tool Only 工具層，不是決策者

Checks if the message pretends to be bank / gov / platform.
檢查訊息是否偽裝成銀行、政府或官方平台。 顯示 / 隱藏 詳細語意角色檢查

此層使用 Ex(y)=π 角色治理模型，確保：

  • AI 與審查工具永遠是「工具層」，不會被當成真正決策者或合約主體。
  • 訊息若偽裝成「銀行／政府／官方平台」，會被標記為較高風險。
  • 最終決策與責任必須回到「人」與「正式機構」，而不是「模型覺得怎樣」。
ENGINE NOTES ｜ 引擎說明
基於 SCBKR 責任鏈、語意風險分級與 Ex(y)=π 角色治理的反詐騙語意防火牆。

SCBKR 責任鏈：
S 主體、C 原因、B 邊界、K 成本、R 責任。
缺 S/C/B 視為「邏輯殘缺」、缺 K/R 則標記為「不可結案 NON-CLOSABLE」，必須有真人或正式機構介入。

Semantic Firewall V3：
將輸出分為 SAFE、RISK、FATAL、NON-CLOSABLE 四類， 並保留可審計的語意紀錄，方便之後追溯與調整規則。

Ex(y)=π 角色治理：
在這套系統裡，AI 只是一層「語意檢查工具」，
不會被視為真正的決策主體，也不能拿來當作推卸責任的藉口。

本 Demo 僅為前端語意治理展示，不會儲存貼上的內容。
實際導入金融機構、政府或平台時，可再串接後端審計與報表系統。

Pro Mode ｜ 專業版：
額外強調：
  • 可將 SCBKR 缺口與風險標籤輸出為 JSON，供 SOC / 風控系統串接。
  • 可將 NON-CLOSABLE 個案送往真人覆核，保留 WORM-LOG 以利稽核。
  • 可視需求加上多語與多模態（語音 / 影像描述）擴充，但 語律與責任鏈 仍為主體。
長輩安心提示：
如果你：
  • 看不懂對方在說什麼、
  • 被催促要「馬上」匯款或提供資料、
  • 對方說自己是銀行或政府，但你沒主動聯絡過對方，
最安全的做法只有一個： 先不要做，打電話給官方或家人，慢慢問清楚再決定。
